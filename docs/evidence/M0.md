## What was built

- `ec-parity verify` ports the web corpus checks (`docs/spec/07` §6): byte count and SHA-256
  of every listed file; the manifest's own SHA-256 pinned in code
  (`4b4bf901d2fadd8bf8266482739a30bd3b19de6dd1cd047fd80f59c0ee3e1fb6`); the rules file
  against the manifest
  (`ecd33cd6bb4010474a471dc2e937f302d14ec6d8aaffcd2b819ab8bb6cc6fa74`); CRLF and BOM;
  files in `inputs/` or `expected/` that the manifest does not list; canonical JSON form;
  `caseId`, `kind` and outcome in every expected file; rule validity, and with
  `--require-frozen` that the rules are frozen, dated, and have no class still `proposed`;
  and that every leaf of every expected output matches exactly one rule. It prints the
  expected-output aggregate SHA-256
  (`76d6ad8b3a2b5d1fe0dbec6b0372676903821332c56fb4ecbe53ec897c1598e6`).
- Integration tests copy the corpus to a temporary folder and damage it one way at a time
  (CRLF, BOM, unlisted file, missing file, edited tolerance, consistently rehashed output,
  leaf without a rule, wrong case header, draft rules); each damage is reported with its
  own problem code. Other tests pin the case inventory (27/20/13/9/5/4/4/2/2 by kind, 43
  per mode, 7 error cases) and the frozen tolerance table (25 classes, 242 rules, frozen on
  2026-11-06).
- The canonical JSON writer reproduces all 86 expected files byte for byte.
- `app_info` returns `ipcVersion` 1, name, version, build commit, profile, platform,
  architecture and `aiAvailable` (false until M9). The UI calls it only through the
  generated `bindings.ts`; a Rust test fails when the bindings are out of date.

## Decisions made in M0

None of these changes the stack in `docs/spec/08` §2, so none needed an ADR.

1. **Bindings:** `specta` =2.0.0-rc.28, `tauri-specta` =2.0.0-rc.29 and
   `specta-typescript` =0.0.15, pinned exactly because they are release candidates. 08 §2
   names `specta` + `tauri-specta`.
2. **TypeScript 6.0.3, not 7:** `typescript-eslint` 8 accepts TypeScript below 6.1.0 only.
3. **pnpm workspace at the repository root** with the UI as its only package, so the
   Tauri CLI (a root dev dependency) finds `apps/desktop/src-tauri`. `minimumReleaseAge` is
   7 days as a supply-chain guard.
4. **Version source:** `tauri.conf.json` has no `version`, so the app and installer use the
   Cargo workspace version (0.1.0). No `license` field is set in any manifest until D1 is
   decided.
5. **Bundle identifier `app.echocanvas.desktop`** is a placeholder (see owner questions).
6. **Build commit:** `build.rs` embeds `git rev-parse --short=12 HEAD` (or `unknown`) so
   `app_info` can report it.
7. **Commands live in `commands.rs`,** not the crate root: a `pub` command in the crate
   root does not compile (`E0255`, `__cmd__app_info` defined twice), and the bindings test
   needs the command to be public.
8. **Windows test binaries:** Tauri test executables fail to start with
   `STATUS_ENTRYPOINT_NOT_FOUND` unless they carry the Common Controls v6 manifest, so
   `build.rs` embeds `windows-app-manifest.xml` into every binary instead of letting
   `tauri-build` embed it into the app binary only (the approach Tauri's own `build.rs`
   takes).
9. **Security baseline:** the CSP from 08 §9 (`default-src 'self'`, no remote origins,
   `connect-src` limited to Tauri IPC), `freezePrototype`, no global Tauri object, and a
   single capability for the main window that allows `app_info` and nothing else. No
   plugins, so the UI has no file system, shell, process or HTTP access.
10. **`ec-parity run`** exists so the AGENTS.md command works, but no case has an adapter
    before M2/M3. It reports the 86 cases as not run and exits with failure rather than
    claiming parity.
11. **CI bundles** one package per OS (NSIS, `.app`, `.deb`) to keep CI time down; no
    signing.
12. **Manifest paths** start with the web repository's `benchmarks/corpus/v1/`; they are
    mapped onto `fixtures/corpus/v1` without editing the manifest
    (`docs/evidence/disagreements.md`, D-M0-1).
13. **Integer-like JSON keys:** JavaScript puts keys such as `"0"` or `"17"` first when it
    builds an object, while the canonical writer sorts all keys by UTF-16 code units. No
    corpus or web-export file has such a key (a Node scan of 178 corpus JSON files and both
    web exports found none), so the corpus cannot tell which the web writer did. Revisit if
    a later format has numeric keys.

## Dependency licenses

Details in `THIRD_PARTY_NOTICES.md`. All 454 third-party crates in `Cargo.lock` are under
permissive licenses or offer one, except seven MPL-2.0 crate versions brought in by Tauri.
Only `option-ext` 0.2.0 is linked into the shipped app (on all three OSes, through
`dirs-sys` → `dirs` → `tauri`/`wry`); the others are compile-time only (`tauri-macros`
proc macro) or not linked for desktop targets. The four npm packages in the shipped UI are
MIT or Apache-2.0/MIT. Development-only npm tools include `lightningcss` (MPL-2.0) and
`caniuse-lite` (CC-BY-4.0). No dependency was chosen for its license; these all come with
Tauri, Vite and ESLint. Whether to accept them is an owner question.
